# 常见问题

症状 → 原因 → 处理。按你看到的现象找。

---

## 一、装了但没反应

### 界面上没有那四行控件

| 可能原因 | 怎么查 | 处理 |
| --- | --- | --- |
| jar 没放进 `mods/`，或放错目录（面板服/多实例） | 启动日志里搜 `MTR4 Advanced` | 放到**实际运行的那个**游戏目录的 `mods/` |
| 装了两份（旧 id 的 jar 还在） | 看 `mods/` 里有没有 `mtr-train-speed-1.0.0.jar` | 删掉旧的，只留 `MTR4Advanced-1.0.1-<MC版本><加载器>.jar` |
| MTR 版本不是 4.0.4 | 看日志里的依赖校验信息 | 换回 4.0.4 |
| 这不是侧线界面 | — | 只有**侧线（Siding）编辑界面**才有这四行，车场/站台界面没有 |

### 游戏启动时直接报依赖错误

```
Mod 'MTR4 Advanced' requires ... mtr ...
Mod 'MTR4 Advanced' is incompatible with ...
```

这是 `fabric.mod.json` 里 `depends` / `breaks` 的正常拦截，不是崩溃：

- `depends.mtr = ">=4.0.4"` → 低于 4.0.4 拒绝启动；
- `breaks.mtr = ">=4.0.5 <4.0.6"` → **4.0.5 拒绝启动**（该版本上注入点不可用，有意为之）。

### 启动日志里没有 `[MTR4 Advanced] 已生成默认配置`

只会在**第一次**（配置文件不存在时）打印。已经生成过就不会再有这行。
想确认加载情况，可以临时把 `config/mtr4-advanced.properties` 删掉重启，看这行是否出现、路径是不是你以为的那个。

## 二、配置相关

### 配置改了没生效

按顺序排：

1. **改的是哪个端？** 限速与时刻表都只在**服务端**算 → 改服务端的 `config/mtr4-advanced.properties`。只改客户端那份对行车没有任何影响。
2. **重启了吗？** 配置只在启动时读一次，**没有热重载**。
3. **文件到底在哪？** 面板服 / systemd / 从别的目录启动时，进程工作目录不是游戏目录。
   看日志里那行 `已生成默认配置: <绝对路径>`，或者按 [配置参考](配置参考.md#一文件到底落在哪) 的规则推。
4. **值的写法对不对？** `Boolean.parseBoolean` 只认 `true`（忽略大小写），
   写 `1` / `yes` / `on` 会**静默变成 false**；`default-max-speed-kmh` 写 `80 km/h` 会解析失败**静默回退 0（不限制）**。
5. **键名拼错** → 该键用默认值，不报错。

### 日志里出现乱码

面板 / 重定向场景下的控制台编码问题，不影响功能。要干净日志：

```powershell
$env:PYTHONIOENCODING = "utf-8"
$OutputEncoding = [Console]::OutputEncoding = [Text.Encoding]::UTF8
```

## 三、行车行为相关

### 列车永远显示晚点

| 原因 | 处理 |
| --- | --- |
| 线路限速 120、列车只能跑 80，但时刻表按 120 算 | 确认 `apply-max-speed-to-time-segments=true`（默认开） |
| 时刻表是质点模型，没算「整列通过才提速」的耗时 | 确认 `apply-vehicle-length-to-time-segments=true`（默认开） |
| 刚改完侧线的车型 / 最高时速 | 需要等列车**重新生成路径**（或重启存档）才会重算时刻表 |
| 中途换过车型 | 时刻表只按侧线**当前**配置算，**不会回溯**修改已生成的计划时间 |

### 列车跑不到设定的最高时速

**这是正常的**：上限是天花板，不是目标。

- 线路限速更低时按线路限速走：最终 `min(线路限速 × 晚点增益, 上限)`；
- 硬顶模式下，晚点追赶作用在**线路限速**上，不是作用在上限上；
- **手动驾驶时三项功能全都不参与**（见下一条）。

### 列车反而超过了最高时速

你勾了「**跟随晚点浮动**」。勾选后上限自己也会跟着晚点增益上浮，最高到 `上限 × 1.25`。
想要绝对守不住不破的硬顶 → **取消勾选**（默认就是不勾）。

### 手动驾驶时完全不受限速 / 上限影响

**已知限制，不是 bug。** `simulateMoving` 里手动分支排在 ATO 路径**之前**且结尾直接跳过 ATO，
本模组的两个注入点都在被跳过的 ATO 路径里。理由与设想见
[已知限制与路线图](已知限制与路线图.md#1-手动驾驶完全不生效)。

### 高密度线路怀疑掉 tick

每次行车计算会做**两次二分查找 + 区间内轨段线性扫描**（`O(log n + k)`）。
目前没有实测到问题，但在超长线路 + 大量列车的服务器上属于已知的累计开销，记录在案未优化。
见 [已知限制与路线图](已知限制与路线图.md#二记录在案尚未处理) 第 7 项。

## 四、侧线界面相关

### 按钮点了显示「已提交 N 条，等待服务端确认」，但重进界面值又变回去了

**服务端把包丢了。** 客户端是先改本地对象再 `sendPacketToServer`，拿不到回执：

| 场景 | 结果 |
| --- | --- |
| 单人世界 / 局域网主机 / OP | 服务端接受，落库 ✓ |
| 多人服非 OP（或没进 dashboard 编辑模式） | 服务端直接丢包 ✗ —— 本地看着改成了，重拉数据后静默回滚 |

→ 用 OP 账号，或确认进入了 dashboard 编辑模式；改完**关掉界面重开一次**确认值还在。
详见 [侧线界面](侧线界面.md#点完到底算不算改成了)。

### 输入框打不出小数点

**已知限制**：输入框的正则过滤器只放行数字，且最多 4 位 → 只能填整数。
（代码里保留了小数显示/格式化的分支，但界面改不出来。）

### 第 3 / 4 行控件看不见 / 画到屏幕外

**已知限制**：这块布局是固定行高、没有滚动条。GUI scale 调大或窗口很矮时会溢出。
→ 临时把 GUI scale 调小 / 把窗口拉高。

### 侧线里改的值重进存档就没了

说明这次修改**没有落库**。依次检查：

1. 服务端装了这个模组吗？**只装客户端**时，服务端不认识这两个字段，值存不进去（不会崩，但也不会保存）。
2. 多人服有 OP / dashboard 编辑权限吗？（同上一条）
3. 装了两份（旧 id + 新 id）时行为不可预期 → 删掉旧的。

## 五、构建 / 校验脚本相关

| 报错 | 处理 |
| --- | --- |
| `找不到 MTR jar，请设置环境变量 MTR_JAR` | `MTR_JAR=/path/to/mtr-fabric-4.0.4.jar python build.py` |
| `警告：没找到 MTR 4.0.4，回退到 ...` | 换回 4.0.4；或确认新版注入点仍有效 |
| `缺少 .../libs/mixin-0.8.7.jar` | 从仓库取这个文件（第三方库，1.4 MB） |
| `stub generation exceeded limit` | 多半不是 stub 的问题，看完整 javac 输出 |
| check_targets：`找不到 MTR jar: <某个绝对路径>` | 脚本里写死的默认路径不是你的路径，用 `--jar` 指定 |
| check_targets：`FileNotFoundError` / 找不到 javap | PATH 上没有 javap，用 `--javap` 指定，或装完整 JDK |
| check_targets：`MISS` | MTR 版本不对，或注入的目标方法改名了 → 运行时一定会 `InvalidInjectionException` |
| check_targets：调用点 `WARN`（≠1） | 宿主方法里目标调用点不唯一 → 给 `@Redirect` 补 `ordinal` 或改注入方式。**这条最危险：可能什么错都不报，只是限速算错** |
| `ALL OK` 但游戏里注入失败 | 检查是不是装了两份模组、MTR 版本是否 4.0.4、是否有别的模组也改了同一个目标类 |

## 六、卸载 / 迁移

| 问题 | 答案 |
| --- | --- |
| 卸载后侧线里存的值会丢吗？ | 不会。服务端读不到对应 Mixin 时会**跳过**这些 key，不清零、不报错。 |
| 重新装回来值还在吗？ | 在。 |
| 只删服务端那份会怎样？ | 行车立刻回到 MTR 原版行为；客户端界面还在，但改的值不会落库。 |
| 从旧版升级要注意什么？ | 必须先删 `mods/mtr-train-speed-1.0.0.jar`，旧配置要手工搬。见 [快速开始](快速开始.md#六从旧版mtr-train-speed迁移)。 |
