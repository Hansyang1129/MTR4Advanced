# 开发指南

面向要改这个模组的人：注入点总表、访问器清单、**加一个新字段的完整清单**、以及踩过的坑。

---

## 一、注入点总表

mixin 配置（`src/main/resources/mtr4-advanced.mixins.json`）：

```json
{
  "required": false,
  "package": "cn.nansai.mtr4advanced.mixin",
  "compatibilityLevel": "JAVA_17",
  "minVersion": "0.8",
  "mixins": [ "SidingMixin", "SidingSchemaMixin", "SidingTimeSegmentsMixin", "VehicleSpeedMixin",
              "access.VehicleAccess", "access.VehicleSchemaAccess" ],
  "client": [ "client.SidingScreenMixin", "access.SavedRailScreenBaseAccess" ],
  "injectors": { "defaultRequire": 1 }
}
```

| # | Mixin 类 | 目标类 | 类型 | 位置 | 作用 |
| --- | --- | --- | --- | --- | --- |
| 1 | `SidingMixin` | `org.mtr.core.data.Siding` | `@Inject` TAIL | `updateData` | 反序列化两个新字段；并让 `Siding` 实现 `SidingMaxSpeedAccess` |
| 2 | `SidingSchemaMixin` | `org.mtr.core.generated.data.SidingSchema` | `@Inject` TAIL | `serializeData` | 把两个新字段写进序列化（存档 + 网络） |
| 3 | `SidingTimeSegmentsMixin` | `Siding` | `@Redirect` | `generatePathDistancesAndTimeSegments` → `Siding#getUpcomingSlowerSpeed` | 借这次调用抓 path / 车头里程 / 车长，并套上限 |
| 4 | `SidingTimeSegmentsMixin` | `Siding` | `@Redirect` | 同方法 → `PathData#getSpeedLimitMetersPerMillisecond` | 占用区间最低限速 + 套上限 |
| 5 | `VehicleSpeedMixin` | `org.mtr.core.data.Vehicle` | `@Redirect` | `simulateMoving` → `PathData#getSpeedLimitMetersPerMillisecond` | **加速目标** |
| 6 | `VehicleSpeedMixin` | `Vehicle` | `@Redirect` | `simulateMoving` → `Siding#getUpcomingSlowerSpeed` | **制动目标** |
| 7 | `SidingScreenMixin`（**client**） | `org.mtr.mod.screen.SidingScreen` | `@Inject` | `init2` TAIL / `tick2` TAIL / `render` TAIL / `onClose2` **HEAD** | 四行界面 |
| 8 | `access.SavedRailScreenBaseAccess`（**client**） | `org.mtr.mod.screen.SavedRailScreenBase` | `@Accessor` | — | 读私有控件与 `textWidth` |

`MIXIN_TARGETS`（`tools/check_targets.py`）里登记的 8 个类与上表一一对应。

### 1.1 四个 `@Redirect` 都依赖「调用点唯一」

宿主方法里每个目标调用点都**恰好 1 次**，所以没有写 `ordinal`：

| 宿主方法 | 目标调用 | 次数 |
| --- | --- | --- |
| `Vehicle#simulateMoving` | `PathData#getSpeedLimitMetersPerMillisecond` | 1 |
| `Vehicle#simulateMoving` | `Siding#getUpcomingSlowerSpeed` | 1 |
| `Siding#generatePathDistancesAndTimeSegments` | `Siding#getUpcomingSlowerSpeed` | 1 |
| `Siding#generatePathDistancesAndTimeSegments` | `PathData#getSpeedLimitMetersPerMillisecond` | 1 |

**改 MTR 版本后必须重跑 `check_targets.py`**：调用点变成 2 处时，`@Redirect` 会静默改错地方。

## 二、访问器清单（`@Accessor`）

| 接口 | 目标类 | 字段 |
| --- | --- | --- |
| `access.VehicleAccess` | `Vehicle` | `siding`、`deviationSpeedAdjustment` |
| `access.VehicleSchemaAccess` | `org.mtr.core.generated.data.VehicleSchema` | `railProgress` |
| `access.SavedRailScreenBaseAccess` | `SavedRailScreenBase` | `savedRailBase`、`showScheduleControls`、`textWidth`、`sliderDwellTimeSec` |

> ⚠️ **`check_targets.py` 不校验 `@Accessor` 的字段名。**
> javap 输出的是 `value="siding"` 这种形式，脚本只解析 `method=` / `target=` 两类注解行 →
> 这 18 项检查里**一项都没有覆盖访问器**。改 MTR 版本时，字段改名不会被脚本拦住，
> 只能在运行时炸 `MixinApplyError` / `NoSuchFieldError`。要补的话得给脚本加一类 `value=` 解析。

## 三、加一个新字段的完整清单

以「再加一个 `departureOffsetSec`（发车补偿秒数）」为例，按顺序做，一步都别跳：

1. **接口**：`api/SidingMaxSpeedAccess.java` 加 getter/setter。
   **必须在 `cn.nansai.mtr4advanced.api` 包里** —— 放进 `mixin` 包会让运行时抛
   `IllegalClassLoadError: ... is in a defined mixin package ... and cannot be referenced directly`。
2. **存字段**：`SidingMixin` 加 `@Unique` 字段（命名保持 `mtr4a$` 前缀）+ 实现接口。
   数值 setter 记得挡 `NaN` / `Infinity`（`Math.max(0, NaN)` 返回 NaN，会一路透传进限速计算）。
3. **反序列化**：`SidingMixin#mtr4a$updateData`（TAIL）里加 `readerBase.unpackXxx("key", ...)`。
   key 名要和写出时**完全一致**。缺失 key 时 `unpackValue` 不会回调 → 不会清零已有值。
4. **序列化**：`SidingSchemaMixin#mtr4a$serializeData`（TAIL）里加 `writerBase.writeXxx("key", ...)`。
   不要在 `SidingMixin` 里试着注入 `serializeData`（见第四节坑 2）。
5. **界面**（可选）：`SidingScreenMixin#mtr4a$init` 里加控件，位置**沿用相对布局**
   （`mtr4a$row1Y()` 的锚点 + 行偏移），不要写死坐标。
   控件创建放在 `if (xxx == null)` 里（resize 会重跑 `init2`），位置每次刷新都要重设。
6. **写回**：`SidingScreenMixin#mtr4a$onClose`（HEAD）里写回 `siding`。
   放在 HEAD 是为了赶在 MTR 自己打包这条侧线之前。
7. **使用**：在 `SpeedLogic` / `SidingTimeSegmentsMixin` 里读，不要在 mixin 的 handler 里堆业务逻辑。
8. **配置**（若需要）：`Config` 加静态字段 + `load()` 里的读取 + `writeDefault()` 的注释与写出。
9. **校验**：如果是**新的 mixin 类**，把它加进 `tools/check_targets.py` 的 `MIXIN_TARGETS`（否则等于没校验）；
   然后：
   ```bash
   python build.py && python tools/check_targets.py --jar <MTR 4.0.4 的 jar>
   ```
   必须 `ALL OK`。
10. **文档**：`README.md` 与对应 wiki 页面同步更新（本项目的历史教训就是「文档写得比实现宽」）。

## 四、踩过的坑

### 1. 普通类不能放进 mixin 包

mixin 配置里 `package` 指向的包（`cn.nansai.mtr4advanced.mixin.*`）下的**所有**类都会被 Mixin 当成 mixin 处理。
把纯接口放进去，运行时报：

```
IllegalClassLoadError: ... is in a defined mixin package ... and cannot be referenced directly
```

→ 纯接口 / 枚举放 `cn.nansai.mtr4advanced.api`。

### 2. Mixin 不会为目标类生成父类方法的 override

想注入 `Siding#serializeData` 是不行的 —— 这个方法声明在 `SidingSchema` 上，`Siding` 只是继承。
Mixin 0.8.7 会报：

```
could not find any targets matching 'serializeData' in org/mtr/core/data/Siding
```

→ 改成注入 `SidingSchema#serializeData`，在 handler 里用 `instanceof Siding` 过滤。

### 3. `@Redirect` 的调用点前提会随 MTR 版本失效

见第一节。脚本能查出来，但**必须记得跑**。

### 4. 客户端专用的 Mixin 要放进 `"client"` 数组

否则专用服务端加载时会因为找不到 `net.minecraft.client.*` / `org.mtr.mod.screen.*` 而 `NoClassDefFoundError`。
当前 `SidingScreenMixin` 与 `SavedRailScreenBaseAccess` 都在 `"client"` 里。

### 5. Screen 实例会在 resize 时被复用

Minecraft 重跑 `init2` 时 **Screen 对象还是同一个**，字段不会重置。
所以：

- 控件只在 `== null` 时创建；
- 复选框的 `setChecked` 只在首次创建时从 `siding` 读（否则会把用户刚勾的状态清掉）；
- 输入框只在文本为空时才用 `siding` 的值填充；
- 每次 `init2` 都要重设 `x/y/width`（窗口尺寸可能变了）。

### 6. `Config` 的初始化必须双检锁 + `volatile`

`loaded` 是跨线程的（渲染线程 / 服务端线程）。两个要点：

- `loaded = true` 必须在**四个字段全部赋值之后**；
- `loaded` 必须是 `volatile`。

违反任一条 → 取决于线程竞争，服务端可能**永久**跑在默认配置上（首轮审查的 P0）。

### 7. 配置目录不要写死 `user.dir`

面板服 / systemd / 从别的目录启动时工作目录不是游戏目录 → 配置写到别处、静默使用默认值。
现在优先走 `FabricLoader#getConfigDir()`（反射调用，编译期不依赖 fabric-loader），失败才回退。

### 8. 中文 UI 字符串目前是硬编码

四个字符串（`列车最高时速 km/h`、`0 = 不限制，留空同 0`、`跟随晚点浮动`、`复制到车场其他侧线`）
直接写在 `SidingScreenMixin` 里，**没有 lang 文件**，非中文客户端也是中文。
要做多语言得引入 `assets/<modid>/lang/*.json` + `Text.translatable`。

### 9. 大车场发包要分批

一条 `Siding` 序列化含 `pathDistances` / `timeSegments` 数组，体积随线路长度增长；
Fabric 自定义 payload 有单包上限。不分批 → 整包被拒 → **连玩家自己这条都存不进去**。
现在按 `MTR4A$BATCH_SIZE = 40` 分批（这个 40 是经验值，没有实测依据，见路线图）。

## 五、调试建议

- **离线校验优先**：改完注入点先跑 `check_targets.py`，比进游戏试快得多。
- **看日志**：`Config` 的提示走 `System.err`（会被收进 `latest.log`），搜 `[MTR4 Advanced]`。
- **加临时日志**：`SpeedLogic` 里把 `rawLimit / occupiedMin / cap / adjustment` 打出来，
  是定位「为什么这列车跑这么慢」最快的手段。
- **规划中的调试 HUD**（实时显示 `target / railLimit / occupiedMin / cap / deviation / powerLevel`）
  是审查清单里性价比最高的一项，见 [已知限制与路线图](已知限制与路线图.md#四路线图)。
