## 用法 A：留在仓库里（默认）

什么都不用做。GitHub 网页预览 Markdown 时，页面之间的相对链接（`[快速开始](快速开始.md)`）可以直接点。

## 用法 B：发布成 GitHub Wiki

GitHub 的 Wiki 是**独立于主仓库的另一个 git 仓库**（`<repo>.wiki.git`），`wiki/` 目录不会自动同步过去。
发布步骤如下：

```bash
# 1) 先在 GitHub 网页上给仓库创建一次 Wiki（创建首页，随便写点东西）
# 2) 克隆 wiki 仓库
git clone https://github.com/<用户名>/<仓库名>.wiki.git
cd <仓库名>.wiki

# 3) 把 wiki/ 里的内容拷进去（Unix / macOS）
cp -r ../mtr-train-speed/wiki/* .
# Windows PowerShell
# Copy-Item ..\mtr-train-speed\wiki\* . -Recurse -Force

# 4) 提交
git add -A
git commit -m "docs: 同步项目 wiki"
git push
```

两点注意：

- **首页要叫 `Home.md`** —— 本目录已经是这个名字，直接覆盖即可。
- **链接写法**：本目录的页面之间用 `[标题](页面名.md)`。GitHub Wiki 对这种写法一般也能正确解析到同名页面；
  如果发现跳转异常，把它换成 wiki 语法的双方括号写法即可（`_Sidebar.md` 已经用的就是 `[[...]]`）。

## 维护约定

1. **改行为就改文档**：本项目的教训是「文档写得比实现宽」——
   已经发生过「降速由车头控制」「复制 = 成功」两处承诺超出实现的情况。
2. **不要再复制一份 README**：同一段内容在两处维护必然发散。
   README 讲「怎么用」，wiki 讲「为什么这样、边界在哪、怎么改」。
3. **改注入点 / MTR 版本后**，[构建与工具](构建与工具.md) 与 [开发指南](开发指南.md) 里的
   预期输出、注入点总表要一起核对。
4. 新增页面记得加进 `_Sidebar.md` 和 [Home.md](Home.md) 的文档地图。
