# 侧线界面

打开侧线（Siding）编辑界面，最下面会多出四行本模组的控件。这一页说明它们怎么用、
什么时候生效、以及为什么文案是「已提交」而不是「已复制」。

---

## 一、四行控件

```
 列车最高时速 km/h            [ 80 ]
 0 = 不限制，留空同 0
 [x] 跟随晚点浮动
 [ 复制到车场其他侧线 ]
```

| 行 | 内容 | 说明 |
| --- | --- | --- |
| 1 | 标签 + 数字输入框 | 单位 km/h，**只填数字**，最多 4 位 |
| 2 | 说明文字 | `0 = 不限制，留空同 0` |
| 3 | 复选框 | `跟随晚点浮动`，默认不勾 |
| 4 | 按钮 | 把当前设置刷到**同一个车场里的其他所有侧线** |

**输入框规则**（实现上是 `TextFieldWidgetExtension(..., maxLength=4, filter="\\D", ...)`）：

- 正则过滤器直接**吞掉非数字字符** → 打不出小数点、负号、字母；
- 最多 4 位 → `0` ~ `9999`；
- 因此**本质上只能填整数**。存过 `80.5` 这类值时显示会保留最多 3 位小数（`mtrspeed$format`），
  但界面上改不回来 —— 这是 [已知限制](已知限制与路线图.md#2-输入框无法输入小数) 之一。

**什么时候写回**：关闭界面时（`onClose2` 的 HEAD）才把输入框和复选框的值写进当前这条侧线对象，
紧接着 MTR 自己的 `onClose2` 才会把这条侧线打包发给服务端。所以：

- 输入框留空 → `Double.parseDouble("")` 抛异常被吞掉 → 按 **0（不限制）** 处理，与第 2 行提示一致；
- 直接在界面里改完**不关界面**，值还没落到侧线对象上；只有「复制」按钮是立即生效的（下一节）。

## 二、布局是相对的，不是写死坐标

```
列：标签贴左边距 20
    控件对齐 MTR 自己那一列 = 20 + textWidth + 2

行：锚点 = MTR 界面上最后一个原生控件 sliderDwellTimeSec
    row1 = anchor.y + anchor.height + 4
    row2 = row1 + 20 + 1     （说明文字，y 是文字顶部）
    row3 = row1 + 20 + 12    （复选框）
    row4 = row3 + 20         （复制按钮）
```

好处：切语言导致 `textWidth` 变化、MTR 增删控件时，这块会自动跟着走。

`sliderDwellTimeSec` 取不到时有兜底：`238 + 20 + 4 = 262`
（238 是 MTR 4.0.4 里 `SidingScreen#setButtons` 写死的 y，这个分支只是保险）。

> **已知问题**：布局固定、**没有滚动**。GUI scale 调大或窗口很矮时，第 3 / 4 行会画出屏幕外。
> 见 [已知限制与路线图](已知限制与路线图.md#3-界面无溢出保护)。

## 三、「跟随晚点浮动」是什么意思

MTR 原版有「晚点追赶」机制：列车晚点时把目标速度乘上 `deviationSpeedAdjustment`（默认最多 **×1.25**）。
这个增益是在**取完限速之后**才乘的，所以「列车最高时速」有两种口径：

设增益 `A = deviationSpeedAdjustment`（≥ 1.0），`cap` = 列车最高时速。

| 勾选状态 | 实现 | 最终目标速度 |
| --- | --- | --- |
| **不勾**（默认，硬顶） | `min(限速, cap / A) × A` | `min(限速 × A, cap)` —— `cap` 绝对不被突破；限速没顶到 `cap` 时，原版晚点追赶照常生效 |
| **勾选**（浮动） | `min(限速, cap) × A` | `min(限速, cap) × A` —— 连 `cap` 一起上浮，最高可到 `cap × 1.25` |

数值例子：

| 场景 | 不勾 | 勾选 |
| --- | --- | --- |
| 限速 40、cap 80、A = 1.25 | `min(40 × 1.25, 80) = 50` | `min(40, 80) × 1.25 = 50` |
| 限速 100、cap 80、A = 1.25 | `min(100 × 1.25, 80) = 80` | `min(100, 80) × 1.25 = 100` |

怎么选：

- 「最高时速 80 就是 80，晚点也别想破」→ **不勾**；
- 「晚点时允许短暂冲到 100 把时间追回来」→ 勾上。

> 想要连原版晚点追赶也一起禁掉、最终严格 = `min(限速, cap)`：
> 把 `SpeedLogic#applyHardCap` 最后一行改成 `Math.min(limit, cap) / safeAdjustment`。
> 目前保留现状的理由是：晚点追赶是 MTR 原版机制，本模组只想加一个**不受增益放大的天花板**。

**时刻表推算那边永远按硬顶处理**（推算时没有「晚点」这个概念），
受 `apply-max-speed-to-time-segments` 控制。

## 四、「复制到车场其他侧线」按钮

把界面上当前的「列车最高时速」+「跟随晚点浮动」一次性刷到**同一个车场（Depot）里的其他所有侧线**，
不用一条条手动改。

### 实现要点：为什么不能只改字段

MTR 的 `SidingScreen#onClose2` 只会把**当前这一条**侧线打包发给服务端；
给别的侧线改字段不会落库。所以这里走 MTR 自己的更新通道：

```java
UpdateDataRequest request = new UpdateDataRequest(MinecraftClientData.getDashboardInstance());
request.addSiding(siding);                       // 自己
int pending = 1;
for (Siding other : depot.savedRails) {
    ...; request.addSiding(other);
    if (++pending >= MTRSPEED$BATCH_SIZE) {      // 满 40 条发一包
        InitClient.REGISTRY_CLIENT.sendPacketToServer(new PacketUpdateData(request));
        request = new UpdateDataRequest(MinecraftClientData.getDashboardInstance());
        pending = 0;
    }
}
if (pending > 0) { ...send... }
```

**为什么要分批**：一条 `Siding` 序列化出来含 `pathDistances` / `timeSegments` 等数组，
体积随线路长度增长，而 Fabric 自定义 payload 有单包上限。不分批的话大车场一旦超限，
**整个包会被拒，连玩家自己这条都存不进去**。所以按 **`MTRSPEED$BATCH_SIZE = 40`** 条一批。

### 点完到底算不算改成了

这里是**先改本地对象、再发请求**，而且拿不到回执（`sendPacketToServer` 无返回值；
`UpdateDataRequest#update()` 那个返回 `UpdateDataResponse` 的同步 API 只有服务端才走）：

| 场景 | 结果 |
| --- | --- |
| 单人世界 / 局域网主机 / OP | 服务端接受，落库 ✓ |
| 多人服非 OP（或没进 dashboard 编辑模式） | 服务端**直接丢包** ✗ —— 本地显示改成了，重进存档 / 重拉 dashboard 数据后静默回滚 |

所以按钮文案刻意写「**已提交**」而不是「已复制」：它只承诺「包发出去了」。三种文案：

| 文案 | 含义 |
| --- | --- |
| `该车场没有其他侧线` | 车场里只有当前这一条（自己的那条仍然会发出去） |
| `已提交 N 条，等待服务端确认` | 只有一包 |
| `已提交 N 条（P 包）` | 分成了多包 → 存在「部分成功」的中间状态（某包超时/被拒时车场里一半改了一半没改） |

> `N` 只数**其他侧线**，不含当前这条。
>
> 多人服上改完想确认有没有真生效：**关掉侧线界面重开一次**，值还在才算落库。

## 五、改完之后什么时候生效

| 改的东西 | 生效时机 |
| --- | --- |
| 列车最高时速 / 跟随晚点浮动 | 关闭界面写回后，服务端下一次行车计算就会用上（还要看服务端有没有接受这次更新） |
| 侧线的车型编组 | 需要等列车**重新生成路径**（或重启存档）才会重算时刻表 |
| 时刻表本身 | 按侧线**当前**配置的车型长度算；中途换车型**不会回溯**修改已生成的计划时间 |

## 六、界面相关的实现索引

| 行为 | 注入点 |
| --- | --- |
| 建控件 / 恢复位置 | `SidingScreen#init2` TAIL |
| 输入框光标闪烁 | `SidingScreen#tick2` TAIL |
| 画标签与说明文字 | `SidingScreen#render` TAIL |
| 关闭时写回字段 | `SidingScreen#onClose2` **HEAD**（必须早于 MTR 自己打包） |
| 读 MTR 的私有成员 | `SavedRailScreenBaseAccess`（`savedRailBase` / `showScheduleControls` / `textWidth` / `sliderDwellTimeSec`） |

这些都在 mixin 配置的 `"client"` 数组里 → **专用服务端不加载**。
