# 变更日志

版本号在三个地方手工同步：`src/main/resources/fabric.mod.json` 的 `version`、
`build.py` 里的 `OUT_JAR` 文件名、以及 README / 本页的说明。改版本时三处都要动。

---

## [1.0.0] —— 2026-09

首个可用版本。三个特性：

1. **提速由车尾控制**：加速目标取「列车占用区间 `[车尾, 车头]` 内的最低线路限速」。
2. **侧线「列车最高时速」**：侧线新增字段 + 「跟随晚点浮动」开关；默认硬顶，任何情况下不突破。
3. **时刻表按车型长度推算**（`apply-vehicle-length-to-time-segments`）：
   把车尾控制提速带来的延迟算进计划时间，消除结构性晚点。

配套：

- 侧线界面新增四行配置区（相对布局，跟随 MTR 自身的 `textWidth` 与最后一个原生控件）。
- 「复制到车场其他侧线」按钮，按 **40 条一批**发送（防止大车场单包超限导致整包被拒）。
- 四个配置项：`tail-controlled-acceleration`、`default-max-speed-kmh`、
  `apply-max-speed-to-time-segments`、`apply-vehicle-length-to-time-segments`。
- 离线构建脚本 `build.py`（只需 JDK 17+）与注入点校验脚本 `tools/check_targets.py`。

## 改名记录 —— 2026-09-19

原名 **MTR Train Speed** → 现名 **MTR4 Advanced**。

| 项 | 旧 | 新 |
| --- | --- | --- |
| mod id | `mtr-train-speed` | `mtr4-advanced` |
| jar | `mtr-train-speed-1.0.0.jar` | `MTR4Advanced-1.0.0.jar` |
| 配置文件 | `config/mtr-train-speed.properties` | `config/mtr4-advanced.properties` |
| mixin 配置 | `mtr-train-speed.mixins.json` | `mtr4-advanced.mixins.json` |

**未改**：Java 包名 `cn.nansai.mtrspeed` 与 mixin 内部的 `mtrspeed$` 前缀（纯内部标识）。

> 升级时**必须删掉旧的 jar**，否则两份 Mixin 会对同一目标重复注入。
> 旧配置文件不会自动迁移，字段要手工搬（旧版只有 3 个键）。

| # | 问题 | 处理 |

| P1-2 | 「硬顶」公式与 README 承诺不符 | 保留实现、**重写文档**为准确公式表（见 [决策记录](已知限制与路线图.md#五决策记录)） |

| P1-2（四轮） | 「复制」在非 OP 多人服是假成功 | 文案改「已提交 N 条，等待服务端确认」，多包时报包数 |
| P2-5…P2-15 | 车长重复计算、`vehicleExtraData` null 防御、`NaN` 穿透 setter、小数截断、无用 accessor、配置静默失败、兜底魔数注释、`build.py` 找 jar 顺序 | 全部已修 |
| N1–N9 | 校验脚本类名打印、README 示例过时、`breaks` 过宽、部分成功提示、跨平台 glob、文档自相矛盾、项数数错、`javap` 在 PATH 上不存在 | 全部已修 |

| P2-1（四轮） | 制动目标也受车尾控制，与文档概括不符 | 同步文档 + 给出「只看车头」的改法 |
